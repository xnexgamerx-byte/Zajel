# وهج العراق على Railway

خدمتان في مشروعٍ واحد: **MySQL**، و**التطبيق** (الويب وPHP والمجدوِل في حاويةٍ
واحدة). وRailway يتولّى الخادم وHTTPS وشهادة النطاقات الفرعية كلّها.

الإعداد كلّه بالنقر، ولا طرفية. والخروج من Railway إلى خادمٍ عادي أمرٌ واحد
(آخر هذه الصفحة).

---

## قبل البدء

| | |
|---|---|
| **حساب Railway** | [railway.com](https://railway.com) ← الدخول بحساب GitHub نفسه الذي فيه المستودع |
| **الباقة** | **Pro** (٢٠ دولاراً شهرياً، يدخل فيها استهلاكٌ بـ ٢٠ دولاراً) طوال التجربة: **النسخ الاحتياطي التلقائي لقاعدة البيانات فيها وحدها**، ومع شحناتٍ وأموالٍ حقيقية لا نعمل بلا نسخ. وHobby (٥ دولارات + الاستهلاك) تكفي لتجربةٍ بلا بياناتٍ حقيقية |
| **نطاق** | **اختياري للبدء**: بدونه يعمل النظام على عنوان Railway المجاني (`xxxx.up.railway.app`) لشركةٍ واحدة. ولأكثر من شركة، أو لعنوانٍ باسمك: نطاقٌ تملكه وتصل إلى إعدادات DNS عنده |

الاستهلاك المتوقّع: نحو ١ غيغابايت ذاكرة (MySQL والتطبيق معاً) وقليلٌ من المعالج —
قرابة ١٠ دولارات شهرياً، أي داخل ما تشمله Pro.

---

## ١. قاعدة البيانات

1. في المشروع: **+ Add ← Database ← MySQL**. لا تغيّر اسمها: متغيّرات التطبيق تشير إليها
   باسم `MySQL`.
2. افتح خدمة MySQL ← **Settings ← Region**: **EU West (Amsterdam)** — الأقرب إلى العراق.
   ولا تغيّر **Source Image**: القاعدة تُنشئ ملفّاتها لحظة إنشاء الخدمة، ونسخةٌ أقدم
   بعدها لا تبدأ عليها.
3. (Pro) **Backups** ← جدولٌ **يومي**.

## ٢. خدمة التطبيق

1. في المشروع نفسه: **New ← GitHub Repo ← Zajel**. تظهر بطاقتها باسم المستودع
   (**Zajel**)، واسمها في Railway وحده: لا يراه أحدٌ غيرك.
2. افتح الخدمة ← **Settings**:

   | الإعداد | القيمة |
   |---|---|
   | **Root Directory** | `/platform` |
   | **Railway Config File** | `/platform/railway.json` |
   | **Region** | **EU West (Amsterdam)** — مع قاعدة البيانات |
   | **Wait for CI** | مفعّل: لا يُنشر تحديثٌ لم تنجح اختباراته |

3. **Variables ← Raw Editor**، والصق (بقيمك):

   ```
   ZAJEL_TENANT_DOMAIN=wahaj.iq
   DB_URL=${{MySQL.MYSQL_URL}}
   ZAJEL_ADMIN_PHONE=07xxxxxxxxx
   ZAJEL_ADMIN_PASSWORD=كلمة-مرور-من-عشرة-أحرف-أو-أكثر
   ```

   `${{MySQL.MYSQL_URL}}` يُكتب كما هو: Railway يضع مكانه عنوان قاعدة البيانات —
   **بشرط أن تكون في المشروع خدمةٌ اسمها `MySQL` تماماً** (الخطوة ١). وإن كان اسمها
   غير ذلك فضعه مكان `MySQL`.

   `ZAJEL_TENANT_DOMAIN`: نطاقك، أو الذي ستشتريه لاحقاً، بأحرفٍ صغيرة. بلا نطاقٍ
   الآن لا يُستعمَل حتى تضيفه.

   وفي **Settings** تأكّد أنّ **Cron Schedule** فارغ: الخدمة تعمل دائماً، والمهامّ الليلية
   تعمل داخلها. جدولٌ هنا يجعلها تعمل ثم تتوقّف (ويظهر تبويب **Cron Runs**).

4. **أوّل نشرٍ يتوقّف عمداً**، وفي **Deploy Logs** سطرٌ كهذا:

   ```
   APP_KEY=base64:…
   ```

   أضفه إلى **Variables**: في **Raw Editor** الصق السطر كما هو؛ وفي **New Variable**
   الاسم `APP_KEY` والقيمة ما بعد `=` وحده (تبدأ بـ `base64:`). **واحفظه عندك في مكانٍ
   آمن**: به تُوقَّع روابط QR على الوصولات، فإن ضاع بطلت كلّها. ثم **Deploy**.
   (يعيد Railway المحاولة، فقد يتكرّر السطر بقيمٍ مختلفة: أيّها يصلح، والمهمّ أن
   يبقى ما حفظته.)

5. في **Deploy Logs** بعد دقائق: `أُنشئ مدير المنصّة 07…`. **احذف الآن
   `ZAJEL_ADMIN_PASSWORD` من Variables** — لا حاجة له بعد، ولا يغيّر شيئاً إن بقي.

## ٣. العنوان — بلا نطاقٍ الآن، أو بنطاقك

### بلا نطاق: عنوان Railway المجاني

شركةٌ واحدة على عنوانٍ واحد: `/admin` للوحة المنصّة، والباقي نظام الشركة.

1. في **Variables** أضف:

   ```
   PORT=8080
   ZAJEL_DEFAULT_COMPANY=barq
   ```

   `barq` مثال: الاسم القصير الذي ستسجّل به شركتك (حروف إنجليزية صغيرة وأرقام وشرطة).
   يصير نطاقها الفرعي حين تضيف النطاق (`barq.wahaj.iq`)، ولا يتغيّر بعد التسجيل.

2. **Settings ← Networking ← Generate Domain**، والمنفذ `8080`. يعطيك Railway
   عنواناً من اسم الخدمة، مثل `zajel-production.up.railway.app`. **ثبّت العنوان قبل
   أوّل وصلٍ تطبعه**: رموز QR تحمله، فتغييره بعدها يُبطلها.
3. افتح `https://<العنوان>/admin/login` ← ادخل برقمك وكلمة المرور ← **الشركات ← تسجيل
   شركة**، و**النطاق الفرعي نفس `ZAJEL_DEFAULT_COMPANY`** (`barq`).
4. `https://<العنوان>` الآن نظام شركتك: منه يدخل الموظّفون والتجّار والمندوبون.

ثلاثة أشياء تختلف عن النظام بنطاق:

- **لوحة المنصّة والشركة على عنوانٍ واحد، فالجلسة واحدة في المتصفّح.** افتح اللوحة
  في **نافذةٍ خاصّة** (Incognito) والشركة في العادية. وبعد «ادخل نظامها» ثم الخروج
  تدخل اللوحة من جديد.
- **رموز QR على الوصولات تحمل هذا العنوان.** حين تضيف نطاقاً لاحقاً أبقِ العنوان
  و`ZAJEL_DEFAULT_COMPANY` حتى تُسلَّم الشحنات التي طُبعت وصولاتها عليه — أيام.
- **شركةٌ واحدة.** الثانية تحتاج نطاقاً.

### بنطاقك

1. خدمة التطبيق ← **Settings ← Networking ← Custom Domain** ← `*.wahaj.iq` (بنجمة).
   نطاقٌ واحد يشمل لوحة المنصّة `admin.wahaj.iq` وكل شركةٍ تُسجَّل بعد اليوم.
2. يعرض Railway سجلّات DNS؛ أضفها كما هي عند مزوّد النطاق. عادةً:

   ```
   CNAME   *                 →  xxxx.up.railway.app
   CNAME   _acme-challenge   →  authorize.railwaydns.net
   ```

   (وقد يطلب سجلّ TXT للتحقّق.) على Cloudflare: السحابة **رمادية** للسجلّين.
3. حين يصير النطاق في Railway أخضر: افتح `https://admin.wahaj.iq/admin/login`.

## ٤. أوّل شركة، وتأكيدٌ واحد

1. ادخل برقمك وكلمة المرور ← **الشركات ← تسجيل شركة** ← نطاقها الفرعي (مثل `barq`)
   — إن لم تسجّلها في الخطوة السابقة.
2. من صفحة الشركة: **«ادخل نظامها»** ثم اخرج. سجلّ الصفحة يُظهر الآن سطرين، وبجانب
   كلٍّ **عنوان IP**. يجب أن يكون **عنوانك أنت** (قارنه بما يُظهره
   [whatismyip.com](https://whatismyip.com))، لا عنواناً يبدأ بـ `10.` أو `100.`.
   هكذا يُعرف أنّ حدّ محاولات الدخول يحسب كل زائرٍ وحده.

ثم الإعداد والتجربة كما في [وثيقة ١٦](../docs/plan/16-pilot-guide.md).

## حين يسقط النشر

خدمة التطبيق ← **Deployments** ← النشر ← **Deploy Logs**:

| في السجلّ | السبب | الحلّ |
|---|---|---|
| `DB_URL وصل فارغاً` — أو `Connection refused … Host: 127.0.0.1 … Database: laravel` | مرجع `DB_URL` لم يجد خدمة قاعدة البيانات | في المشروع خدمةٌ اسمها `MySQL` تماماً (إن لم تكن: **+ Add ← Database ← MySQL**)، و`DB_URL=${{MySQL.MYSQL_URL}}`، ثم **Deploy** بعد أن تخضرّ |
| `DB_URL لم يصل إلى هذه الخدمة` | المتغيّر ليس في متغيّرات التطبيق، أو لم يُحفَظ (✓)، أو حُفظ ولم يُطبَّق | أضفه في **Variables** التطبيق نفسها، واحفظه، ثم **Deploy** (لا Redeploy لنشرٍ قديم). وسطر «متغيّرات القاعدة التي وصلت» تحته يقول ما وصل فعلاً |
| `APP_KEY مفقود` | لم يُضَف المفتاح بعد | الخطوة ٢ · ٤ |
| `APP_KEY غير صالح` — أو `Unsupported cipher or incorrect key length` | القيمة ناقصة أو فيها زيادة | القيمة `base64:` ثم ٤٤ حرفاً، لا أقلّ. (`APP_KEY=` قبلها وعلامات التنصيص تُصحَّح وحدها) |
| `قاعدة البيانات لم تجب بعد (محاولة …)` | MySQL يبدأ | لا شيء: ينتظرها دقيقةً ثم يكمل |
| تبويب **Cron Runs** و«Next in …» على بطاقة التطبيق | جدولٌ في **Cron Schedule** | **Settings ← Cron Schedule**: امسحه |
| **Unexposed service**، ولا عنوان | لا عنوان مجاني ولا نطاق | الخطوة ٣ |
| صفحة ٤٠٤ على العنوان المجاني | `ZAJEL_DEFAULT_COMPANY` لم يصل (أُضيف ولم يُنشَر بـ **Deploy**)، أو لا شركة بنطاقه الفرعي | لوحة المنصّة (`/admin`) تقول أيّهما في أعلى كل صفحة، وما تفعل |

## العمل اليومي

| | |
|---|---|
| **السجلّات** | خدمة التطبيق ← **Deployments ← View Logs** |
| **التحديثات** | كل دفعةٍ إلى GitHub تُنشر وحدها بعد نجاح اختباراتها. ولتتحكّم بموعدها أثناء التجربة: **Settings** ← أوقف النشر التلقائي، وانشر بنفسك ليلاً |
| **الكلفة** | **Usage** يُظهرها؛ وضع **Usage Limit** (٣٠ دولاراً مثلاً) فلا تُفاجأ بفاتورة |
| **نسيت كلمة مرور المدير** | خدمة التطبيق ← **⋯ ← SSH** (أو `railway ssh`)، ثم `php artisan zajel:admin 07xxxxxxxxx` |

## الخروج من Railway إلى خادمٍ عادي

كل شيءٍ ينتقل: الحسابات بكلمات مرورها، والشحنات، والمال، والإعدادات — ورموز QR
المطبوعة تبقى تعمل.

1. جهّز الخادم الجديد وانسخ المشروع إليه (الخطوة ٢ في [README](README.md)).
2. في Railway، خدمة التطبيق ← آخر نشر ← **⋯ ← Remove**: يتوقّف النظام فلا يُكتب
   فيه شيءٌ بعد النسخة. (قاعدة البيانات تبقى تعمل.)
3. على الخادم الجديد:

   ```bash
   cd /opt/zajel/deploy
   sudo ./from-railway.sh
   ```

   يسأل أربعة: **MYSQL_PUBLIC_URL** (خدمة MySQL ← Variables)، و**APP_KEY** (خدمة
   التطبيق ← Variables)، والنطاق، والبريد. ثم ينسخ القاعدة ويشغّل كل شيء.
4. عند مزوّد النطاق: احذف سجلّي Railway (`*` و`_acme-challenge`)، وأضف:

   ```
   A   wahaj.iq      →  عنوان الخادم الجديد
   A   *.wahaj.iq    →  عنوان الخادم الجديد
   ```

5. بعد أن تتأكّد أنّ كل شيءٍ يعمل هناك يوماً أو يومين: احذف مشروع Railway.
