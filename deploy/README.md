# تشغيل وهج العراق على خادم

> **على Railway بدل خادمٍ خاص؟** [railway.md](railway.md) — بالنقر، بلا طرفية.

خادمٌ واحد يحمل كل شيء: التطبيق (PHP 8.5)، وقاعدة البيانات (MySQL 8.4)،
وخادم الويب (Caddy) بشهادات HTTPS تُصدَر وحدها لكل شركة، والمجدوِل الليلي،
والنسخ الاحتياطي. كلّه في Docker، فلا يُثبَّت على الخادم نفسه غير Docker.

```
deploy/
├─ setup.sh      التثبيت الأول — مرّةً واحدة
├─ update.sh     التحديث لآخر نسخة (بنسخةٍ احتياطية قبله)
├─ backup.sh     النسخة الاحتياطية (كل ليلة تلقائياً)
├─ export.sh     النقل إلى خادمٍ آخر — حزمةٌ واحدة بكل شيء
├─ from-railway.sh  من Railway إلى خادمٍ عادي
├─ railway.md    التشغيل على Railway
├─ compose.yaml  الحاويات الأربع
├─ Caddyfile     خادم الويب والشهادات
└─ .env          الإعداد والأسرار — يكتبه setup.sh، ولا يُرفع إلى GitHub أبداً
```

---

## ما يلزم قبل البدء

| | |
|---|---|
| **خادم** | Ubuntu 24.04 أو 26.04، أو Debian 12 أو 13. معالجان و**٤ غيغابايت ذاكرة** و٤٠ غيغابايت قرص تكفي شركةً بآلاف الشحنات يومياً. أيّ مزوّد: Hetzner أو DigitalOcean أو Contabo أو مزوّدٌ عراقيّ |
| **نطاق** | أيّ نطاقٍ تملكه (مثل `wahaj.iq` أو `wahaj-app.com`). كل شركةٍ تعمل على نطاقٍ فرعيّ منه: `barq.wahaj.iq`، ولوحتك على `admin.wahaj.iq` |
| **منافذ مفتوحة** | ٢٢ (SSH)، و٨٠ و٤٤٣ (الويب). من جدار الحماية عند المزوّد إن كان له جدار |

## الخطوات

### ١. سجلّات DNS — قبل كل شيء

عند مزوّد النطاق أضف سجلّين يشيران إلى عنوان IP الخادم:

```
A    wahaj.iq      →  203.0.113.10
A    *.wahaj.iq    →  203.0.113.10
```

السجلّ الثاني (النجمة) هو ما يجعل كل شركةٍ جديدة تعمل بلا سجلٍّ جديد.
وخلف Cloudflare — وهو الأفضل — اتبع [«خلف Cloudflare»](#خلف-cloudflare--الحماية-مجاناً) بدل هذه الخطوة.

انتظر حتى يصل: `ping admin.wahaj.iq` من جهازك يجب أن يُظهر عنوان الخادم.
الشهادة لا تُصدَر لنطاقٍ لا يشير إلى الخادم بعد.

### ٢. نسخ المشروع إلى الخادم

```bash
ssh root@203.0.113.10
git clone https://github.com/xnexgamerx-byte/Zajel.git /opt/zajel
cd /opt/zajel/deploy
```

### ٣. التثبيت

```bash
sudo ./setup.sh
```

يسأل ثلاثة أسئلة: النطاق، وبريدٌ لتنبيهات الشهادات، ورقم هاتف مدير المنصّة
(ثم كلمة مروره مرّتين، عشرة أحرفٍ على الأقل). والباقي وحده:

- يثبّت Docker إن غاب؛
- يكتب `.env` بأسرارٍ عشوائية (مفتاح التطبيق وكلمتَي سرّ قاعدة البيانات)؛
- يبني الصور ويشغّلها (أول مرّة: خمس دقائق تقريباً)؛
- يزرع البيانات المرجعية: المحافظات، وأسباب التعذّر، وفئات المصروفات، والباقات؛
- يُنشئ مدير المنصّة؛
- يضبط النسخة الاحتياطية كل ليلة في ٣:٣٠ فجراً بتوقيت بغداد.

> **احفظ نسخةً من `deploy/.env` خارج الخادم** (في مدير كلمات مرور مثلاً).
> فيه `APP_KEY` الذي تُوقَّع به روابط التتبّع المطبوعة على الوصولات: إن ضاع
> وأُعيد التثبيت بمفتاحٍ جديد، بطل رمز QR على كل وصلٍ طُبع قبله.

### ٤. أول شركة

1. افتح `https://admin.wahaj.iq/admin/login` وادخل برقمك وكلمة مرورك.
2. **الشركات ← تسجيل شركة**: اسمها، ونطاقها الفرعيّ (مثل `barq`)، وحساب صاحبها.
3. يعمل نظامها فوراً على `https://barq.wahaj.iq` — أول زيارةٍ تستغرق ثواني
   ريثما تُصدَر الشهادة، ثم لا شيء.

## خلف Cloudflare — الحماية مجاناً

Cloudflare أمام الخادم يصدّ هجمات DDoS والهجمات الشائعة (WAF)، ويخفي عنوان الخادم،
ويقدّم ملفات التصميم من أقرب مركزٍ للزائر — في خطّته المجانية. والخادم عندها لا يطلب
شهادات من Let's Encrypt: شهادة Cloudflare للمصدر تغطّي النطاق وكل نطاقاته الفرعية،
فكل شركةٍ تُسجَّل تعمل فوراً.

### ١. النطاق في Cloudflare

1. [dash.cloudflare.com](https://dash.cloudflare.com) ← **Add a site** ← `wahaj.iq` ← **Free**.
2. عند مسجّل النطاق غيّر الـ**Nameservers** إلى الاثنين اللذين يعرضهما Cloudflare. انتظر حتى
   يصير النطاق **Active** (دقائق إلى يوم).
3. **DNS** ← سجلّان، والسحابة **برتقالية** (Proxied):

   ```
   A    @    →  عنوان الخادم
   A    *    →  عنوان الخادم
   ```

   لا تحذف سجلّاً موجوداً لا تعرفه (بريدٌ إلكترونيّ مثلاً): سجلّات MX وTXT تبقى رمادية.

### ٢. شهادة المصدر — قبل التثبيت

1. **SSL/TLS ← Origin Server ← Create Certificate**: RSA (2048)، والنطاقان كما يقترحهما
   (`wahaj.iq` و`*.wahaj.iq`)، والمدّة ١٥ سنة ← **Create**.
2. على الخادم، بعد نسخ المشروع (الخطوة ٢ أعلاه):

   ```bash
   cd /opt/zajel/deploy && mkdir -p certs
   nano certs/origin.pem     # الصق «Origin Certificate» كاملاً، ثم Ctrl+O وEnter وCtrl+X
   nano certs/origin.key     # الصق «Private Key» كاملاً
   ```

   **المفتاح يظهر في Cloudflare مرّةً واحدة**: احفظ نسخةً منه في مكانٍ آمن. وإن ضاع فأنشئ
   شهادةً جديدة وضعها مكانه.
3. **SSL/TLS ← Overview ← Full (strict)**. لا Flexible أبداً: تحويلٌ لا ينتهي، واتصالٌ غير
   مشفّر بين Cloudflare والخادم.

### ٣. التثبيت

`sudo ./setup.sh` كما في الخطوة ٣ أعلاه، وأجب **نعم** عن «هل النطاق خلف Cloudflare؟».
يتأكّد قبل أن يبدأ أنّ الشهادة شهادة، وأنّ المفتاح مفتاحها، وأنها تشمل `*.wahaj.iq` —
ويجلب عناوين Cloudflare من [cloudflare.com/ips](https://www.cloudflare.com/ips/): منها وحدها
يُصدَّق عنوان الزائر، فحدّ محاولات الدخول يحسب كل زائرٍ وحده، ولا يزوّر أحدٌ عنوانه من
خارجها. (`update.sh` يجدّدها في كل تحديث.)

### ٤. جدار الحماية — فلا يتخطّى أحدٌ Cloudflare

من يعرف عنوان الخادم يستطيع أن يصله مباشرةً فيتجاوز الحماية. أغلق الويب إلا عن Cloudflare
في **جدار الحماية عند المزوّد** — لا ufw على الخادم: Docker يفتح منافذه من تحته.

في Hetzner: **Firewalls ← Create Firewall**، ثم **Apply to** الخادم:

| Inbound | المنفذ | المصدر |
|---|---|---|
| SSH | TCP 22 | عنوانك، أو Any إن كان عنوانك يتغيّر |
| HTTP وHTTPS | TCP 80 و443 | عناوين Cloudflare: `grep CLOUDFLARE_RANGES .env` يطبعها |

### ٥. إعدادات Cloudflare — المجانية كلّها

| أين | الإعداد |
|---|---|
| **SSL/TLS ← Edge Certificates** | Always Use HTTPS: تشغيل · Minimum TLS: 1.2 · TLS 1.3: تشغيل · **HSTS: اتركه** — التطبيق يرسله بنفسه |
| **Security ← WAF ← Managed rules** | **Cloudflare Free Managed Ruleset** مفعّل (افتراضياً — تأكّد) |
| **Security ← DDoS** | لا شيء: الحماية تلقائية ودائمة في كل الخطط |
| **Security ← Bots** | Bot Fight Mode **مطفأ**: لا يُستثنى منه شيءٌ في الخطة المجانية، وقد يعترض تطبيقاً أو أداة مراقبة |
| **Security ← WAF ← Rate limiting** (اختياري) | قاعدةٌ واحدة مجاناً: `POST` على `/login` و`/admin/login`، عشرة طلبات كل ١٠ ثوانٍ لكل IP — سخيّةٌ عمداً: شبكات الهاتف تُشرك عنواناً واحداً بين كثيرين |
| **Caching** | **لا تغيير**. الصفحات لا تُخزَّن (يرسل التطبيق `no-cache, private` مع كل صفحة)، وملفات `/build/` تُخزَّن سنة. ولا تفعّل **Cache Everything** ولا **Rocket Loader** (يعيد كتابة السكربتات فيكسر الصفحات) |

### ٦. تأكّد

- `https://admin.wahaj.iq/admin/login` يفتح بقفلٍ سليم، وفي رؤوس الردّ (أدوات المطوّر ← Network)
  `cf-ray`، و`cf-cache-status: DYNAMIC` للصفحة و`HIT` لملفات `/build/` من المرّة الثانية.
- `https://barq.wahaj.iq/admin` يعطي ٤٠٤: لوحة المنصّة على admin وحده.
- لوحة المنصّة ← صفحة شركة ← «ادخل نظامها» ثم اخرج: عنوان IP في سجلّها **عنوانك**، لا عنوانٌ
  لـ Cloudflare (يبدأ بـ 104. أو 172.6 أو 162.158).
- وعنوان الخادم مباشرةً (`https://عنوان-الخادم`) لا يجيب بعد جدار الحماية.

## شهر التجربة، ثم البقاء أو النقل

الخادم ليس قراراً نهائياً: النظام لا يرتبط بمزوّدٍ بعينه، وكل ما يخصّ الشركات
في شيئين — قاعدة البيانات و`deploy/.env` — ينتقلان معاً بأمرين.

### من اليوم الأول

- **مزوّدٌ يحاسب بالشهر أو بالساعة**، بلا عقدٍ سنويّ: تتركه متى شئت.
- **مدّة TTL لسجلّي DNS خمس دقائق** (300 ثانية) عند مزوّد النطاق: يوم تنقل،
  يصل العنوان الجديد إلى الناس في دقائق لا في ساعات.
- **النسخة خارج الخادم** (rclone، في قسم النسخ الاحتياطي أدناه)، **ونسخةٌ من `.env`
  عندك**: بهما تنقل حتى لو تعطّل الخادم القديم ولم يعد يُفتح.

### خادمٌ أكبر عند المزوّد نفسه — الأسهل

من لوحة المزوّد: **Resize** (أو Rescale / Upgrade). يُطفأ الخادم دقائق ويعود بذاكرةٍ
ومعالجاتٍ أكثر، بالعنوان نفسه والبيانات نفسها؛ والحاويات تعود وحدها. ثم أعطِ قاعدة
البيانات ربع الذاكرة الجديدة:

```bash
cd /opt/zajel/deploy
sudo nano .env                 # DB_BUFFER_POOL=2G مثلاً لخادمٍ بـ ٨ غيغابايت
sudo docker compose up -d
```

### إلى مزوّدٍ آخر

| # | أين | ماذا |
|---|---|---|
| ١ | — | خادمٌ جديد فارغ (Ubuntu أو Debian)، ومنافذه ٢٢ و٨٠ و٤٤٣ مفتوحة |
| ٢ | القديم | `sudo ./export.sh` — **يوقف الموقع** (فلا يُكتب شيءٌ يضيع)، ويأخذ نسخةً أخيرة، ويحزمها مع `.env`، ويطبع الأوامر التالية بأسمائها |
| ٣ | جهازك | `scp root@القديم:/var/backups/zajel/zajel-move-….tar.gz root@الجديد:/root/` |
| ٤ | الجديد | `git clone https://github.com/xnexgamerx-byte/Zajel.git /opt/zajel && cd /opt/zajel/deploy` ثم `sudo ./setup.sh --restore /root/zajel-move-….tar.gz` |
| ٥ | مزوّد النطاق | سجلّا DNS (النطاق و`*.`النطاق) ← عنوان الخادم الجديد |
| ٦ | المتصفّح | ادخل لوحة المنصّة، وافتح آخر شحنةٍ في شركة. ثم احذف الحزمة من الجهازين (فيها كل الأسرار)، وأوقف القديم بعد يومٍ أو يومين بلا مشكلة |

**ينتقل كلّ شيء:** الشركات، والحسابات بكلمات مرورها، والجلسات (لا يُطلب من أحدٍ الدخول
من جديد)، والشحنات، والمال، والإعدادات. **ورموز QR على الوصولات المطبوعة تبقى تعمل**:
مفتاح التطبيق في الحزمة. والشهادات تُصدَر على الجديد وحدها.

**الانقطاع** من الخطوة ٢ إلى أن يصل DNS: ربع ساعةٍ عادةً مع TTL قصير. اختر وقتاً هادئاً،
بعد منتصف الليل مثلاً. **وإن تراجعت** قبل الخطوة ٥: على القديم `docker compose start web scheduler`.

`setup.sh --restore` لا يعمل على خادمٍ يعمل عليه النظام بالفعل: الاسترجاع يمحو القاعدة،
فلا يُمحى نظامٌ حيّ بخطأٍ في اسم ملف.

**وإن كان القديم معطّلاً لا يُفتح:** اصنع الحزمة بيدك من نسختك من `.env` وآخر نسخةٍ
خارجية، ثم أكمل من الخطوة ٤:

```bash
mkdir move && cd move
cp /path/to/saved/.env .env
cp /path/to/zajel-20260925-003000.sql.gz database.sql.gz
tar -czf ../zajel-move.tar.gz .env database.sql.gz
```

## العمل اليومي

كل الأوامر من `/opt/zajel/deploy`:

| | |
|---|---|
| الحالة | `docker compose ps` — أربع حاويات: app و scheduler و web و db |
| سجلّ الأخطاء | `docker compose logs -f app` |
| إعادة التشغيل | `docker compose restart` |
| التحديث | `sudo ./update.sh` — نسخةٌ احتياطية، ثم الشيفرة، ثم البناء؛ الترحيلات تجري وحدها. الانقطاع دقيقة تقريباً: اختر وقتاً هادئاً |
| نسيت كلمة مرور المدير | `docker compose exec -u www-data app php artisan zajel:admin 07xxxxxxxxx` بالرقم نفسه |

## النسخ الاحتياطي

كل ليلة في `/var/backups/zajel`، ويُحفظ أربعة عشر يوماً (`BACKUP_KEEP_DAYS`).
والسجلّ في `/var/log/zajel-backup.log`. ونسخةٌ يدوية في أيّ وقت: `sudo ./backup.sh`.

**نسخةٌ على الخادم نفسه لا تنفع يوم يضيع الخادم.** لنسخةٍ خارجه (Google Drive،
أو Backblaze، أو خادمٍ آخر) عبر [rclone](https://rclone.org):

```bash
sudo apt install rclone
sudo rclone config                   # أنشئ وجهةً باسم gdrive مثلاً
# ثم في deploy/.env:
BACKUP_REMOTE=gdrive:zajel-backups
```

### الاسترجاع — جرّبه مرّةً قبل أن تحتاجه

```bash
# يمسح ما في القاعدة الآن ويضع النسخة مكانه
gunzip -c /var/backups/zajel/zajel-20260925-003000.sql.gz \
  | docker compose exec -T db sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysql -uroot zajel'
docker compose restart app scheduler
```

وللتجربة بلا مساسٍ بالقاعدة الحيّة: استرجع إلى قاعدةٍ أخرى وقارن الأعداد:

```bash
docker compose exec -T db sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysql -uroot -e "CREATE DATABASE restore_test"'
gunzip -c /var/backups/zajel/zajel-….sql.gz \
  | docker compose exec -T db sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysql -uroot restore_test'
docker compose exec -T db sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysql -uroot -e \
  "SELECT (SELECT COUNT(*) FROM zajel.shipments), (SELECT COUNT(*) FROM restore_test.shipments); DROP DATABASE restore_test"'
```

## حين لا يعمل شيء

| العَرَض | السبب الأرجح |
|---|---|
| المتصفّح يقول «الاتصال غير آمن» أو لا يفتح الموقع | سجلّ DNS لم يصل بعد، أو المنفذ ٨٠ مغلق (الشهادة تُثبَت عبره). `docker compose logs web` يقول السبب |
| نطاق شركةٍ جديدة لا يفتح وغيره يعمل | الاسم مكتوبٌ خطأً، أو الشركة غير مسجّلة: الخادم لا يُصدر شهادةً إلا لنطاق شركةٍ موجودة |
| صفحة ٥٠٢ | التطبيق يبدأ (ترحيلات بعد تحديث) أو توقّف: `docker compose logs app` |
| صفحة ٥٠٠ | خطأ في التطبيق، وتفصيله في `docker compose logs app` |
| القرص امتلأ | `docker system prune` يحذف صور البناء القديمة؛ والنسخ الاحتياطية في `/var/backups/zajel` |

## ما يحرسه هذا الإعداد

- **الشهادات:** تُصدَر لنطاق كل شركةٍ مسجّلة عند أول زيارة، وتُجدَّد وحدها. قبل
  الإصدار يسأل الخادمُ التطبيقَ (`/_tls/allowed`) هل النطاق لشركة، فلا تُطلَب
  شهاداتٌ لأسماءٍ مخترعة تستنفد حدّ Let's Encrypt.
- **لوحة المنصّة** على `admin.` وحده؛ على نطاق أيّ شركة تُرجع ٤٠٤.
- **قاعدة البيانات** لا منفذ لها خارج الخادم.
- **الأسرار** في `.env` بصلاحية المدير وحده، ولا تدخل صورة Docker ولا GitHub.
- **الحراسة:** كل دفعةٍ إلى GitHub تبني هذه الصور وتشغّلها وتسألها (مهمّة
  `deploy` في `.github/workflows/tests.yml`)، فلا يكتشف الخادمُ يوم التحديث
  Dockerfile مكسوراً.
