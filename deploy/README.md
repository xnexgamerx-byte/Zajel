# تشغيل زاجل على خادم

خادمٌ واحد يحمل كل شيء: التطبيق (PHP 8.5)، وقاعدة البيانات (MySQL 8.4)،
وخادم الويب (Caddy) بشهادات HTTPS تُصدَر وحدها لكل شركة، والمجدوِل الليلي،
والنسخ الاحتياطي. كلّه في Docker، فلا يُثبَّت على الخادم نفسه غير Docker.

```
deploy/
├─ setup.sh      التثبيت الأول — مرّةً واحدة
├─ update.sh     التحديث لآخر نسخة (بنسخةٍ احتياطية قبله)
├─ backup.sh     النسخة الاحتياطية (كل ليلة تلقائياً)
├─ compose.yaml  الحاويات الأربع
├─ Caddyfile     خادم الويب والشهادات
└─ .env          الإعداد والأسرار — يكتبه setup.sh، ولا يُرفع إلى GitHub أبداً
```

---

## ما يلزم قبل البدء

| | |
|---|---|
| **خادم** | Ubuntu 24.04 أو 26.04، أو Debian 12 أو 13. معالجان و**٤ غيغابايت ذاكرة** و٤٠ غيغابايت قرص تكفي شركةً بآلاف الشحنات يومياً. أيّ مزوّد: Hetzner أو DigitalOcean أو Contabo أو مزوّدٌ عراقيّ |
| **نطاق** | أيّ نطاقٍ تملكه (مثل `zajel.iq` أو `zajel-app.com`). كل شركةٍ تعمل على نطاقٍ فرعيّ منه: `barq.zajel.iq`، ولوحتك على `admin.zajel.iq` |
| **منافذ مفتوحة** | ٢٢ (SSH)، و٨٠ و٤٤٣ (الويب). من جدار الحماية عند المزوّد إن كان له جدار |

## الخطوات

### ١. سجلّات DNS — قبل كل شيء

عند مزوّد النطاق أضف سجلّين يشيران إلى عنوان IP الخادم:

```
A    zajel.iq      →  203.0.113.10
A    *.zajel.iq    →  203.0.113.10
```

السجلّ الثاني (النجمة) هو ما يجعل كل شركةٍ جديدة تعمل بلا سجلٍّ جديد.
إن كان النطاق على Cloudflare فاجعل السجلّين **DNS only** (السحابة رمادية).

انتظر حتى يصل: `ping admin.zajel.iq` من جهازك يجب أن يُظهر عنوان الخادم.
الشهادة لا تُصدَر لنطاقٍ لا يشير إلى الخادم بعد.

### ٢. نسخ المشروع إلى الخادم

```bash
ssh root@203.0.113.10
git clone https://github.com/xnexgamerx-byte/Zajel.git /opt/zajel
cd /opt/zajel/deploy
```

### ٣. التثبيت

```bash
sudo ./setup.sh
```

يسأل ثلاثة أسئلة: النطاق، وبريدٌ لتنبيهات الشهادات، ورقم هاتف مدير المنصّة
(ثم كلمة مروره مرّتين، عشرة أحرفٍ على الأقل). والباقي وحده:

- يثبّت Docker إن غاب؛
- يكتب `.env` بأسرارٍ عشوائية (مفتاح التطبيق وكلمتَي سرّ قاعدة البيانات)؛
- يبني الصور ويشغّلها (أول مرّة: خمس دقائق تقريباً)؛
- يزرع البيانات المرجعية: المحافظات، وأسباب التعذّر، وفئات المصروفات، والباقات؛
- يُنشئ مدير المنصّة؛
- يضبط النسخة الاحتياطية كل ليلة في ٣:٣٠ فجراً بتوقيت بغداد.

> **احفظ نسخةً من `deploy/.env` خارج الخادم** (في مدير كلمات مرور مثلاً).
> فيه `APP_KEY` الذي تُوقَّع به روابط التتبّع المطبوعة على الوصولات: إن ضاع
> وأُعيد التثبيت بمفتاحٍ جديد، بطل رمز QR على كل وصلٍ طُبع قبله.

### ٤. أول شركة

1. افتح `https://admin.zajel.iq/admin/login` وادخل برقمك وكلمة مرورك.
2. **الشركات ← تسجيل شركة**: اسمها، ونطاقها الفرعيّ (مثل `barq`)، وحساب صاحبها.
3. يعمل نظامها فوراً على `https://barq.zajel.iq` — أول زيارةٍ تستغرق ثواني
   ريثما تُصدَر الشهادة، ثم لا شيء.

## العمل اليومي

كل الأوامر من `/opt/zajel/deploy`:

| | |
|---|---|
| الحالة | `docker compose ps` — أربع حاويات: app و scheduler و web و db |
| سجلّ الأخطاء | `docker compose logs -f app` |
| إعادة التشغيل | `docker compose restart` |
| التحديث | `sudo ./update.sh` — نسخةٌ احتياطية، ثم الشيفرة، ثم البناء؛ الترحيلات تجري وحدها. الانقطاع دقيقة تقريباً: اختر وقتاً هادئاً |
| نسيت كلمة مرور المدير | `docker compose exec -u www-data app php artisan zajel:admin 07xxxxxxxxx` بالرقم نفسه |

## النسخ الاحتياطي

كل ليلة في `/var/backups/zajel`، ويُحفظ أربعة عشر يوماً (`BACKUP_KEEP_DAYS`).
والسجلّ في `/var/log/zajel-backup.log`. ونسخةٌ يدوية في أيّ وقت: `sudo ./backup.sh`.

**نسخةٌ على الخادم نفسه لا تنفع يوم يضيع الخادم.** لنسخةٍ خارجه (Google Drive،
أو Backblaze، أو خادمٍ آخر) عبر [rclone](https://rclone.org):

```bash
sudo apt install rclone
sudo rclone config                   # أنشئ وجهةً باسم gdrive مثلاً
# ثم في deploy/.env:
BACKUP_REMOTE=gdrive:zajel-backups
```

### الاسترجاع — جرّبه مرّةً قبل أن تحتاجه

```bash
# يمسح ما في القاعدة الآن ويضع النسخة مكانه
gunzip -c /var/backups/zajel/zajel-20260925-003000.sql.gz \
  | docker compose exec -T db sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysql -uroot zajel'
docker compose restart app scheduler
```

وللتجربة بلا مساسٍ بالقاعدة الحيّة: استرجع إلى قاعدةٍ أخرى وقارن الأعداد:

```bash
docker compose exec -T db sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysql -uroot -e "CREATE DATABASE restore_test"'
gunzip -c /var/backups/zajel/zajel-….sql.gz \
  | docker compose exec -T db sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysql -uroot restore_test'
docker compose exec -T db sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysql -uroot -e \
  "SELECT (SELECT COUNT(*) FROM zajel.shipments), (SELECT COUNT(*) FROM restore_test.shipments); DROP DATABASE restore_test"'
```

## حين لا يعمل شيء

| العَرَض | السبب الأرجح |
|---|---|
| المتصفّح يقول «الاتصال غير آمن» أو لا يفتح الموقع | سجلّ DNS لم يصل بعد، أو المنفذ ٨٠ مغلق (الشهادة تُثبَت عبره). `docker compose logs web` يقول السبب |
| نطاق شركةٍ جديدة لا يفتح وغيره يعمل | الاسم مكتوبٌ خطأً، أو الشركة غير مسجّلة: الخادم لا يُصدر شهادةً إلا لنطاق شركةٍ موجودة |
| صفحة ٥٠٢ | التطبيق يبدأ (ترحيلات بعد تحديث) أو توقّف: `docker compose logs app` |
| صفحة ٥٠٠ | خطأ في التطبيق، وتفصيله في `docker compose logs app` |
| القرص امتلأ | `docker system prune` يحذف صور البناء القديمة؛ والنسخ الاحتياطية في `/var/backups/zajel` |

## ما يحرسه هذا الإعداد

- **الشهادات:** تُصدَر لنطاق كل شركةٍ مسجّلة عند أول زيارة، وتُجدَّد وحدها. قبل
  الإصدار يسأل الخادمُ التطبيقَ (`/_tls/allowed`) هل النطاق لشركة، فلا تُطلَب
  شهاداتٌ لأسماءٍ مخترعة تستنفد حدّ Let's Encrypt.
- **لوحة المنصّة** على `admin.` وحده؛ على نطاق أيّ شركة تُرجع ٤٠٤.
- **قاعدة البيانات** لا منفذ لها خارج الخادم.
- **الأسرار** في `.env` بصلاحية المدير وحده، ولا تدخل صورة Docker ولا GitHub.
- **الحراسة:** كل دفعةٍ إلى GitHub تبني هذه الصور وتشغّلها وتسألها (مهمّة
  `deploy` في `.github/workflows/tests.yml`)، فلا يكتشف الخادمُ يوم التحديث
  Dockerfile مكسوراً.
