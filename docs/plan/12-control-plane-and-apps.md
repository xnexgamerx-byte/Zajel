# نواة التحكم والتطبيقات — استكمال المواصفات

> تصحيح: المستند ١١ حدّد **نظام الشركة الواحدة** (٢٤ شاشة) ولم يحدّد **لوحتك أنت**.

## ١. المعمارية كاملةً

```
╔══════════════════════════════════════════════════════════╗
║        نواة التحكم  —  admin.نطاقك                        ║
║                    أنت وحدك                               ║
║   تسجيل الشركات · الباقات · الفوترة · المراقبة · الدعم     ║
╚═══════════════════════════╤══════════════════════════════╝
                            │ تُنشئ مستأجراً
        ┌───────────────────┼───────────────────┐
        ▼                   ▼                   ▼
   ┌─────────┐        ┌─────────┐        ┌─────────┐
   │ شركة أ  │        │ شركة ب  │        │ شركة ج  │
   │ ٢٤ شاشة │        │ ٢٤ شاشة │        │ ٢٤ شاشة │
   │ بياناتها│        │ بياناتها│        │ بياناتها│
   │ وحدها   │        │ وحدها   │        │ وحدها   │
   └────┬────┘        └────┬────┘        └────┬────┘
        │                  │                  │
        ├── تطبيق المندوب      ← تطبيق واحد · شعار كل شركة بعد الدخول
        ├── تطبيق/لوحة التاجر
        └── بوابة تتبع الزبون  ← بعلامة كل شركة
```

> **كود واحد · نشر واحد · قاعدة واحدة.** وكل شركة ترى نظامها وحده.
> وهذا ما يفعله النظام المرجعي حرفياً: `branchCode` في الجلسة، وقائمة تبديل الفروع.

## ٢. 🆕 لوحة التحكم — ٨ شاشات (وهي ملكك وحدك)

| # | الشاشة | المحتوى |
|---|---|---|
| ١ | **تسجيل شركة جديدة** | الاسم · الشعار · النطاق الفرعي · المحافظات · المدير الأول · الباقة |
| ٢ | **قائمة الشركات** | نشطة · موقوفة · منتهية الاشتراك — مع تفعيل/إيقاف فوري |
| ٣ | **الباقات** | تعريف الخطط: عدد المستخدمين · المناديب · الشحنات شهرياً · السعر |
| ٤ | **اشتراك كل شركة** | الباقة · تاريخ الانتهاء · التجديد · **خطّ زمني للانتهاءات** ← منسوخ من المرجع |
| ٥ | **الفوترة والتحصيل** | فواتير · مدفوعات · متأخرات |
| ٦ | **المراقبة** | لكل شركة: الشحنات · المستخدمون · المناديب · آخر نشاط |
| ٧ | **الدخول كشركة** (Impersonate) | للدعم الفني — **وكل دخول يُسجَّل في التدقيق** |
| ٨ | **الإعدادات العامة** | المحافظات · المناطق · **الحالات الموحّدة** · العملة |

### ⚠️ شاشتان لا تُؤجَّلان
```
② إيقاف شركة فوراً        ← حين تتوقف عن الدفع. بلاها تخسر مالك
⑦ الدخول كشركة للدعم      ← بلاها كل مشكلة تحتاج بيانات دخول العميل
```

### قاعدة صارمة
> **الشركة لا ترى لوحة التحكم إطلاقاً، وأنت ترى كل شيء — لكن كل اطّلاع يُسجَّل.**
> `branch_id = null` في جلستك يعني «المشرف الأعلى»، وكل استعلام عابر يمرّ بمسار واحد مسجَّل.

## ٣. 📱 التطبيقات — القرار الذي يحدد تكلفتك

قلتَ: «تطبيقات خاصة بكل شركة اللي اني اسويها». هذا يحتمل معنيين، والفرق بينهما **هائل**:

### الحساب الحقيقي عند ١٠ شركات

| | **تطبيق واحد** ✅ | **تطبيق لكل شركة** |
|---|---|---|
| حسابات مطوّر Apple | ١ × ٩٩$ سنوياً | **١٠ × ٩٩$ = ٩٩٠$ سنوياً** |
| حسابات Google Play | ١ × ٢٥$ مرة | ١٠ × ٢٥$ |
| **إصلاح خطأ واحد** | نشرة واحدة · مراجعة واحدة | **١٠ نشرات · ١٠ مراجعات** |
| زمن نشر التصحيح | ١–٣ أيام | **٢–٤ أسابيع** |
| إطلاق شركة جديدة | **فوري** | ١–٣ أسابيع انتظار المتاجر |
| أيقونات وصور ووصف | مرة واحدة | لكل شركة |

> **تخيّل خطأ في حساب تسوية النقد وعندك ١٠ تطبيقات.** شهر كامل حتى يصل التصحيح لكل المناديب — وأنت تعتذر يومياً.

### ✅ الحل: تطبيق واحد يتلوّن بعد الدخول
```
المندوب يفتح التطبيق
    ↓
يدخل برقم هاتفه
    ↓
الخادم يعرف شركته من الحساب
    ↓
يُحمّل شعارها وألوانها واسمها
    ↓
المندوب يرى «تطبيق شركته»
```
**التخصيص بيانات لا كود.** والشركة تغيّر شعارها من لوحتها دون أن تلمس التطبيق.

### وبوابة التتبع هي الاستثناء الوحيد
```
تتبع.شركة-أ.نطاقك   ← بشعارها وألوانها كاملةً
```
لأن **الزبون النهائي** يراها، وهي واجهة الشركة أمام السوق. وهي **صفحة ويب** — تخصيصها ساعات لا أسابيع.

### 💡 ومتى تعطي شركة تطبيقاً باسمها؟
اجعلها **ميزة في الباقة الأعلى بسعر إضافي** يغطي كلفتك الحقيقية:
> «تطبيق باسم شركتك على المتاجر — رسم تأسيس + اشتراك سنوي.»
تحوّل عبئاً إلى مصدر دخل، ولا تمنحها مجاناً لأحد.

## ٤. الحجم النهائي للمشروع

```
لوحة التحكم (لك)          ٨ شاشات
نظام الشركة               ٢٤ شاشة   ← يُبنى مرة ويخدم الجميع
تطبيق المندوب             ويب متجاوب أولاً
لوحة التاجر               ضمن الـ٢٤
بوابة التتبع              صفحة واحدة
────────────────────────────────────
                        ٣٢ شاشة + بوابة
```

### الترتيب الصحيح — ولماذا
```
١. نظام الشركة أولاً (الدفعة ١)
     ↓  شغّل شركة واحدة فعلياً — شركتك أو أول عميل
٢. لوحة التحكم (٨ شاشات)
     ↓  عند اقتراب الشركة الثانية
٣. الباقات والفوترة
     ↓  عند أول اشتراك مدفوع
٤. التطبيقات
     ↓  بعد استقرار كل ما سبق
```

> ⚠️ **لا تبنِ لوحة التحكم أولاً.** لوحة تدير شركات لا وجود لها = شهر ضائع.
> **لكن ضع `branch_id` في كل جدول من أول migration** — وقتها إضافة اللوحة أسبوع لا إعادة بناء.

## ٥. الخلاصة

| سؤالك | الجواب |
|---|---|
| نظام أساسي أنا المتحكم؟ | ✅ **٨ شاشات** — تسجيل · باقات · فوترة · مراقبة · دعم |
| كل شركة لها نظامها؟ | ✅ **٢٤ شاشة** — كود واحد، وكل شركة ترى بياناتها وحدها |
| مثل اللي دزّيته؟ | ✅ **نفس المبدأ تماماً** — `branchCode` وتبديل الفروع |
| يربط بتطبيقات كل شركة؟ | ✅ **تلقائياً** — الخادم يحلّ الشركة من حساب المستخدم |
| تطبيق لكل شركة؟ | ❌ **تطبيق واحد يتلوّن** — والتطبيق المستقل ميزة مدفوعة |
